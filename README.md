# نظام إعداد جدول أقساط — رواسين (خادم حقيقي)

خادم مستقل بالكامل (Node.js + Express + قاعدة بيانات SQLite خاصة به) يحل محل الاعتماد على Airtable أو أي تخزين خارجي. تسجيل الدخول حقيقي بكلمات مرور مُشفَّرة (bcrypt) وجلسات محمية بـ JWT.

## المحتويات
```
server.js          # الخادم الرئيسي وكل الـ API
db.js              # إعداد قاعدة البيانات + البيانات الافتراضية عند أول تشغيل
auth.js            # التحقق من تسجيل الدخول والصلاحيات
seed-units.json     # بيانات الـ 69 وحدة الافتراضية (كمبوند + مول)
package.json
public/index.html   # واجهة البرنامج (نفس الواجهة اللي كنت بتستخدمها، لكن متصلة بالخادم ده بدل Airtable)
data/                # هنا هيتولد ملف قاعدة البيانات rawasin.db تلقائيًا (لا تحذفه بعد أول تشغيل!)
```

## التشغيل على جهازك (لتجربته أولًا)

يتطلب [Node.js](https://nodejs.org) نسخة 18 أو أحدث.

```bash
cd rawasin-server
npm install
npm start
```

هيفتح على `http://localhost:3000` — افتحه في المتصفح، هتلاقي شاشة الدخول تظهر مباشرة (بدون أي إعداد قاعدة بيانات).

**بيانات الدخول الأولى (غيّرها فورًا):**
- اسم المستخدم: `admin`
- كلمة المرور: `admin123`

أول ما تشغّل الخادم لأول مرة، هيتولد ملف `data/rawasin.db` تلقائيًا ويتعبى بالبيانات الافتراضية (الوحدات + الأدوار + حساب admin). المرات اللاحقة هيستخدم نفس الملف ويحافظ على كل تعديلاتك.

## النشر على الإنترنت (عشان يبقى شغال من أي جهاز بدون تشغيله على جهازك)

بما إني مش أقدر أستضيف الخادم بنفسي، أسهل وأرخص طريقة تعمل بيها ده بنفسك:

### الطريقة الموصى بها: Render.com (فيه خطة مجانية)

1. اعمل حساب مجاني على [render.com](https://render.com)
2. ارفع محتويات المجلد ده على مستودع GitHub (أو استخدم "Deploy from a Git repo" لو عندك حساب GitHub بالفعل)
3. من Render: **New → Web Service** → اختار المستودع
4. الإعدادات:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Environment Variable:** أضف `JWT_SECRET` بقيمة عشوائية طويلة وسرية (مهم جدًا لأمان الجلسات — لا تسيبه بالقيمة الافتراضية في الكود)
5. اضغط Deploy — بعد دقيقتين هيديك رابط زي `https://rawasin-app.onrender.com`
6. افتح الرابط ده مباشرة — البرنامج والخادم شغالين على نفس العنوان، فمش هتحتاج تظبط "عنوان الخادم" في شاشة الدخول

**ملحوظة عن الخطة المجانية في Render:** الخادم بينام بعد فترة عدم استخدام، وأول طلب بعد النوم بياخد حوالي 30-50 ثانية يصحّى. لو ده مزعج، الخطط المدفوعة (~7 دولار شهريًا) بتخليه شغال باستمرار.

### بديل: نشر الواجهة والخادم منفصلين

لو حبيت تنشر ملف `public/index.html` على استضافة ثابتة (Netlify/Vercel) والخادم على Render بشكل منفصل:
1. انشر الخادم (server.js وباقي الملفات ما عدا public/) على Render زي فوق، وهياخد رابط زي `https://rawasin-api.onrender.com`
2. انشر ملف `public/index.html` لوحده على Netlify (drag & drop)
3. افتح الملف من نتفلاي، اضغط "⚙️ عنوان الخادم" في شاشة الدخول، والصق رابط الخادم من Render

## الأمان — نقاط مهمة

- **كلمات المرور مُشفَّرة** بـ bcrypt في قاعدة البيانات، مش نص عادي — حتى لو حد وصل لملف قاعدة البيانات مباشرة، مش هيقدر يقرأ كلمات المرور
- **غيّر متغير `JWT_SECRET`** في بيئة الاستضافة (Render → Environment) لقيمة عشوائية طويلة قبل الاستخدام الفعلي — القيمة الافتراضية في الكود للتجربة المحلية فقط
- **غيّر كلمة مرور admin** فورًا بعد أول دخول من تبويب "إدارة المستخدمين"
- التوكن (JWT) صالح لمدة 12 ساعة، وبعدها لازم تسجّل دخول تاني

## النسخ الاحتياطي

ملف قاعدة البيانات `data/rawasin.db` هو كل بياناتك. خده نسخة احتياطية دوريًا (انسخ الملف ده وخزّنه في مكان آمن). لو بتستخدم Render، فعّل "Persistent Disk" من إعدادات الخدمة عشان الملف ميتمسحش عند إعادة النشر.

## الفرق عن النسخة اللي كانت بتستخدم Airtable

- مفيش أي توكن أو مفتاح API ظاهر في كود الواجهة — كل حاجة حساسة (التحقق من كلمة المرور) بتحصل داخل الخادم فقط
- تسجيل الدخول حقيقي (الخادم هو اللي بيتحقق من كلمة المرور، مش المتصفح)
- قاعدة بيانات حقيقية بتتحمّل بيانات أكبر بكثير من حدود Airtable (خصوصًا الرسومات الهندسية)
